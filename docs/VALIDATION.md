# Карта проверки для системного аналитика

## Границы системы

Это демонстрационный frontend на GitHub Pages. В репозитории нет исходника
развёрнутой Cloud Function, базы заказов, webhook-обработчика или подтверждения
серверного статуса платежа. Наличие публичного ID не доказывает тестовый режим:
он задаётся на стороне терминала. Проверять оплату следует тестовыми реквизитами.

## Данные и правила

В localStorage сохраняются только ID и количество. При загрузке неизвестные ID
отбрасываются, повторы объединяются, количество ограничивается 999. Цены берутся
из каталога, сумма строки равна цене × количеству. orderSnapshot содержит items,
itemCount, totalAmount, currency и необязательный orderId (сейчас обычно null).
Данные карты и криптограмма не должны попадать в storage, события и логи.
sessionStorage хранит только сумму и время попытки для модалки (срок 1 час).

## Контракт Checkout, реализованный клиентом

POST `${paymentConfig.checkoutApi}/payment`, JSON:

```json
{"cardCryptogramPacket":"<одноразовая криптограмма>","items":[{"id":1792768165569,"quantity":1}]}
```

| Ответ | Действие |
| --- | --- |
| success=true, status=paid | Очистить корзину, полная загрузка главной |
| success=false, status=declined | Сохранить корзину, главная с модалкой отказа |
| success=true, status=requires3ds | POST формы банка: MD, PaReq, TermUrl |
| Сбой сети, HTTP-ошибка, иной ответ после отправки | unknown; не повторять запрос автоматически |

Для 3DS требуются acsUrl (HTTPS), paReq, transactionId (цифры), termUrl строго
равный адресу Gateway + /post3ds. Сервер возвращает пользователя с параметром
payment=success/failed/unknown. Этот параметр управляет UI и не является
доказательством списания. Очистка демо-корзины не означает выдачу товара.

## Матрица приёмки

1. Добавить две кепки и носки: 3 единицы, 4690 ₽; обновить страницу.
2. Проверить уменьшение количества, удаление, восстановление повреждённого storage.
3. Для каждого сценария проверить success, fail/cancel и повторную оплату.
4. Checkout: пустое имя отсутствует; CVV 3 цифры; номер группируется по 4.
5. Checkout: успех без 3DS очищает корзину до перехода; отказ сохраняет её.
6. 3DS: успех/отказ/unknown; отдельно сверить результат в CloudPayments.
7. Сбой сети после отправки не должен автоматически создавать новый платёж.
8. Навигация во время загрузки SDK не должна монтировать покинутую форму.
9. Режим изучения: Escape, восстановление фокуса, прокрутка; телефон и desktop.
10. После публикации проверить новые файлы без старого браузерного кеша.

## Итоги ревью и открытые вопросы (30.10.2026)

Исправлено: очистка корзины при paid без 3DS; дублирование Public ID;
разрозненные таймауты; зависимость результата блоков от поля status в callback;
обработка запоздалого callback демонтированных блоков; устаревшее README.
JS, CSS, HTML и тесты отформатированы без перестановки CSS-правил.

Остаётся для отдельной проверки backend:
- Исходник функции отсутствует: нельзя подтвердить серверные цены, права,
  идемпотентность, проверку статуса, webhook-подписи и обработку повторного 3DS.
- В предоставленном ранее коде функции предел quantity был 99, клиент допускает
  999. Нужно согласовать фактически развёрнутый лимит; тесты репозитория его не проверяют.
- unknown после сетевого сбоя требует сверки операции; клиентская блокировка
  не заменяет серверную идемпотентность.
- Параметр payment=success можно ввести вручную. Он очищает только демо-корзину;
  его нельзя использовать для исполнения реального заказа.
- CSS содержит исторические переопределения. Они сохранены намеренно: удаление
  требует сравнения всех экранов и брейкпоинтов, а не только unit-тестов.
- Статические HTML дублируют шапку/футер; это цена прямого входа без сборщика.

Автотесты используют моки SDK. Они не подтверждают реальную оплату, работу
Cloud Function или визуальную идентичность. В этом ревью платежи не выполнялись.
